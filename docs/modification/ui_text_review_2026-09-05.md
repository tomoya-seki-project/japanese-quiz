目標已按使用者最新補充更新為：**一般使用者 UI 使用日文；僅管理員可見的文字保留英文，只修正文法及用字**。解釋欄保留繁體中文。管理員專用的回饋處理頁、審批訊息及新申請通知也按英文處理；不是只按 /admin/ 路徑分類。原英文可用的管理員項目標示為「英文保留」。

## 閱讀方式

- 每個來源位置獨立記錄，因此同一句出現在不同模板或分支時會有多筆。
- 位置格式為 `相對檔案路徑:className:functionName:行數`；不存在的部分省略。保留相對路徑，避免多個 forms.py／views.py 混淆。
- 「原始程式碼行」保留來源證據；「原句」可以是獨立標籤、句子、動態模板，或 Django 自動產生的可見標籤。不是每項都可直接用字串取代。
- 「明確錯誤」類型包括拼字、文法、標題錯誤及語意錯誤；「一致性／清晰度／用字建議」並不代表原句文法有錯。
- 日文用語統一為「単語」「マイ単語帳」「お知らせ」「ヒント」「回答」「正解／不正解」「出題対象」。訊息使用自然的敬體，按鈕以簡短明確的動作表達；新增、変更、削除入口明確標示為申請。既有自然日文保留；ID、JLPT、N1 等通用識別方式可保留。
- 動態文字建議中新增的 `{request_type_label}` 等佔位符不是現有變數；內部類別值、顯示標籤與事件值應分開處理。CSV 並不是可直接套用的程式補丁。

## 檢查範圍

已檢查五個應用程式的專案模板、前端 JavaScript，以及現行表單、view、service、model choices／verbose_name 和自訂 admin 中的介面文字來源；另檢查路由、測驗設定與假名鍵盤常數，追查實際操作語意。包括一般訪客、登入使用者、管理員、錯誤頁、驗證訊息、通知及未確認引用的模板。未確認可達的來源已在 CSV 標示。

已查看分類 CSV 的名稱／顯示名稱，記錄介面誤顯示內部分類代碼的問題。字庫匯入 CSV 的日文單字、讀音、詞義及題目屬學習資料，未做逐筆語言或知識正確性校對。資料庫中既有通知、管理員自由輸入回覆、使用者回饋內容也未讀取或逐句校對；修改通知產生文案不會自動更新歷史資料。

一般使用者日文化需要依介面分流 Django 語系，而非把全站一律切成 ja：保留 en-us 預設，一般使用者 request／view 使用 ja；管理員專用介面維持英文，HTML lang 亦應配合。管理員開啟一般使用者頁面時，仍沿用該頁的日文。這些已列入 CSV 為依賴項，並非畫面原句。Django 內建文案不逐條複製入 CSV；啟用日文後仍須實際驗證認證、驗證錯誤、後台模型名稱及自訂欄位標籤。瀏覽器原生驗證訊息可能受瀏覽器語系影響。開發文件、測試預期值、日誌及只在管理指令終端機顯示的訊息不列入 UI 文案翻譯。沒有啟動網站或逐頁操作，因此這是原始碼層面的文案盤點，不宣稱涵蓋所有執行環境或所有動態資料。

## 管理員英文與共用來源

模型 verbose_name、choices、共用模板及通知服務不能只按檔案所在位置判斷語言。管理員專用模型標籤保留英文；一般使用者表單已有獨立 label 的位置採日文。共用 choices 需使用依介面語系翻譯的標籤或分開顯示映射，保留原始儲存值。管理員收取的新申請通知為英文，申請人收到的審批結果通知為日文。CSV 只記錄建議，未實作語系分流。另移除先前誤列的 add_error 欄位鍵 password；該鍵不是可見文案。
