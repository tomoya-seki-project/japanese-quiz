Step 目的 Command / 設定 確認結果
1 更新 Ubuntu package list 
sudo apt update
 Package list 正常更新，沒有 error。
2 安裝 PostgreSQL 
sudo apt install postgresql postgresql-contrib
 PostgreSQL server 及相關工具安裝完成。
3 確認 PostgreSQL service 
sudo systemctl status postgresql
 正常情況會見到： 
Active: active (exited)
PostgreSQL 的總管理 service 顯示 active (exited) 可以是正常狀態。
4 確認 PostgreSQL cluster 正在運行 
pg_lsclusters
 例如： 
Ver Cluster Port Status Owner
16  main    5432 online postgres
重點： Status = online
5 以 PostgreSQL administrator 進入 psql 
sudo -u postgres psql
 成功後會見到： 
postgres=#
# 表示目前是 PostgreSQL superuser。
6 查看現有 database 
\l
 顯示 PostgreSQL 目前所有 database。
7 查看現有 PostgreSQL roles / users 
\du
 可以看到例如： postgres
8 建立 Django 專用 PostgreSQL user 
CREATE USER japanese_quiz_app
WITH PASSWORD '你的密碼';
 成功會顯示： 
CREATE ROLE
9 建立 Japanese Quiz database 
CREATE DATABASE japanese_quiz
OWNER japanese_quiz_app;
 成功會顯示： 
CREATE DATABASE
10 確認 database owner 
\l
 應該見到： 
japanese_quiz | japanese_quiz_app
11 退出 PostgreSQL administrator 
\q
 返回普通 Linux terminal。
12 測試 Django 專用 PostgreSQL user 是否可以登入 
psql -h localhost \
-U japanese_quiz_app \
-d japanese_quiz
 輸入 password 後，成功會見到： 
japanese_quiz=>
> 表示是普通 PostgreSQL user， 不是 superuser。
13 確認目前 PostgreSQL connection 
\conninfo
 應該會見到類似： 
You are connected to database "japanese_quiz"
as user "japanese_quiz_app"
on host "localhost"
at port "5432".
14 在 Django venv 安裝 PostgreSQL driver 
pip install "psycopg[binary]"
 安裝： 
psycopg
psycopg-binary
15 確認 psycopg 安裝 
pip show psycopg
或： 
pip freeze | grep psycopg
 例如： 
psycopg==3.3.5
psycopg-binary==3.3.5
16 更新 requirements.txt 如果使用 pip freeze： 
pip freeze > requirements.txt
 requirements 內應該包含： 
psycopg==3.3.5
psycopg-binary==3.3.5
17 安裝 .env reader 
pip install python-dotenv
 Django 可以從 local .env file 讀取 DB credentials。
18 建立 .env 
DB_NAME=japanese_quiz
DB_USER=japanese_quiz_app
DB_PASSWORD=你的密碼
DB_HOST=localhost
DB_PORT=5432
 Database password 不需要直接寫在 settings.py。
19 防止 .env 被 commit 在 .gitignore 加： 
.env
 執行： 
git status
不應該看到 .env 被 Git track。
20 讓 Django 載入 .env 在 settings.py： 
from pathlib import Path
import os

from dotenv import load_dotenv

BASE_DIR = Path(__file__).resolve().parent.parent

load_dotenv(BASE_DIR / ".env")
 Django 啟動時會讀取 .env。
21 將 Django DATABASES 改成 PostgreSQL 
DATABASES = {
    "default": {
        "ENGINE": "django.db.backends.postgresql",
        "NAME": os.environ["DB_NAME"],
        "USER": os.environ["DB_USER"],
        "PASSWORD": os.environ["DB_PASSWORD"],
        "HOST": os.environ["DB_HOST"],
        "PORT": os.environ["DB_PORT"],
    }
}
 Django 不再使用： 
django.db.backends.sqlite3
改為： 
django.db.backends.postgresql
22 建立 PostgreSQL database schema 
python manage.py migrate
 因為 PostgreSQL database 是全新的， Django 會重新 apply 所有歷史 migration。 例如： 
Applying contenttypes.0001_initial... OK
Applying auth.0001_initial... OK
Applying admin.0001_initial... OK
...
這只是重建 schema， 不代表搬了 SQLite 舊 data。
23 確認 migration 狀態 
python manage.py showmigrations
 已 apply 的 migration 會顯示： 
[X]
24 確認 Django 真正使用 PostgreSQL 
python manage.py shell -c \
"from django.db import connection; print(connection.vendor)"
 應該輸出： 
postgresql
25 確認 PostgreSQL 已建立 Django tables 
psql -h localhost \
-U japanese_quiz_app \
-d japanese_quiz
然後： 
\dt
 應該會看到： 
django_migrations
django_session
auth_...
以及自己 app 的 tables
26 啟動 Django 作最終測試 
python manage.py runserver
 網站正常啟動， 沒有 PostgreSQL connection error。
27 重新建立 admin account 
python manage.py createsuperuser
 因為沒有搬 SQLite data， PostgreSQL 裡需要重新建立 user / superuser。
28 重新加入 application 基礎資料 使用 project 本身的 import command，例如： 
python manage.py import_vocab ...
 重新建立 vocab、category 等需要的資料。
