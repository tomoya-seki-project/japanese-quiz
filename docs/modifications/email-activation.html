Email activation：註冊、確認啟用與重寄流程

核心改修已完成

改修概要

Public registration 原本會立即建立可登入帳戶並同步個人字庫，未能證明使用者真正控制該 email。改修後先保存 inactive user，再以有時限、會隨帳戶狀態失效嘅 activation token 完成 GET 確認及 POST 啟用；成功後先同步字庫，寄信失敗或連結過期亦有重寄同 cooldown 復原流程。後續再將 development console backend 換成由 environment variables 配置嘅 Zoho SMTP，並以 App Password、已建立寄件 alias、Port 465 implicit SSL 完成真實寄送。

主要修改重點

  • Public registration 只建立 inactive user，成功 activation 後先開放登入及同步字庫。
  • Activation link 以 uid 定位帳戶、以 timestamped HMAC token 驗證有效性。
  • GET 只顯示確認頁，真正改變 is_active 嘅操作留俾重新驗證 token 嘅 POST。
  • 寄信失敗會保留帳戶並導向 resend；cache cooldown 減少短時間重複寄送。
  • Zoho SMTP 已成功完成 SSL 登入、真實寄送同 mailbox 收件確認；共享 cache、併發同 activation 專用 automated tests 仍未完成。

前後差異與運作解釋

呢個 class 沿用父類 make_token()／check_token()，只 override「用邊啲帳戶資料參與 hash」。父類使用 server secret 同 HMAC 產生驗證值，再附帶 timestamp；唔係將密碼或 secret 放入 URL。user.password 係 database 已 hash 嘅 password field。

驗證時會用 URL timestamp 同當前 user state 重算，再比對 token，同時檢查 timeout。False → True 改變 is_active 後，重算值不同，之前 token 就唔再通過；email 或 password 改變亦一樣。呢個係根據狀態失效，冇額外 token table 或 used-token record。

要分清楚三件事：

  • uidb64 只係 URL-safe encoding，用嚟定位 user，唔係加密或權限證明。
  • Token 才係驗證依據；持有有效 link 嘅人可以進入確認流程。
  • Resend 只重新產生 token，冇保存「最新 token」或撤銷版本，所以唔保證舊 link 即時失效。同一 user state、同一秒內亦可能產生相同 token。

當前 subclass 唔包含 last_login，亦冇另設 key_salt。唔應誤寫成完整照搬預設 password-reset hash fields，或者聲稱已建立獨立 token 儲存系統。

新使用技術

PasswordResetTokenGenerator 係 Django Auth 既有 generator；今次將其 timestamp、HMAC 同 timeout 機制重用於 activation。_make_hash_value() 係 framework 內部方法，升級 Django 時應重新核對。本次已直接讀取安裝版本 django/contrib/auth/tokens.py；官方 source 入口本次載入失敗，因此細節以本機 6.0.5 源碼為證據。

PASSWORD_RESET_TIMEOUT 以秒計；呢個 subclass 沿用同一設定，所以將來若加入 password reset，兩個用途會共用 timeout。Django timeout 設定

force_bytes()／URL-safe Base64 配對處理 uid；反方向用 urlsafe_base64_decode() 同 force_str()。reverse() 依 named route 建立 path，而 build_absolute_uri() 補上 request 嘅 scheme 同 host，令 email 裏面條 link 可以獨立開啟。Django build_absolute_uri

前後差異與運作解釋

Django嘅smtp.EmailBackend會將既有send_mail()內容交畀SMTP server。今次provider設定係Port 465 implicit SSL，所以EMAIL_USE_SSL=True、EMAIL_USE_TLS=False；兩者唔可以同時開。Port 587 STARTTLS係另一種連線方式，唔應混用。

Environment variables全部係字串。bool("False")喺Python仍然係True，所以設定要用.lower() == "true"轉成真正boolean；亦要記得lower係method，漏咗()只會比較method object，結果會靜默變成False。manage.py check未必捉到呢種意圖錯誤，因此今次另外檢查Django runtime settings。

EMAIL_HOST_USER係真正用App Password登入Zoho嘅mailbox；DEFAULT_FROM_EMAIL可以係同一地址，或者provider已批准嘅alias。今次先喺Zoho建立alias，再以該alias作From地址；未建立就只喺Django自行填寫，可能被provider當成unauthorized sender或relay拒絕。

連線測試先用get_connection().open()驗證host、SSL同credential，成功後立即close，將authentication同真正寄信分開診斷。再用send_mail()由alias寄到帳戶自己嘅mailbox；Django回傳1，使用者亦確認實際收到，證明唔止係console output或SMTP接受但未見收件。
